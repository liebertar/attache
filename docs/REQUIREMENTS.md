# 요구사항 — 사용자가 말한 것 전부

이 문서는 사용자가 세션에서 직접 말한 요구사항만 모은 것입니다. 제가 판단해서 넣은 것은
`(제안)` 으로 표시했습니다. 상태는 **됨 / 부분 / 안 됨** 셋뿐이고, 부분과 안 됨에는
무엇이 남았는지 적었습니다. 다음 사람이 이 문서만 읽고 이어받을 수 있어야 합니다.

## D. 사용자가 물은 것 (답변 완료, 코드 없음)

- **판정은 Nvidia 모델이 하나?** → 아니오. 전부 결정적 코드. 모델은 신청서 작성과 중재
  후보 선택만 하고, 못 하면 규칙이 대신함.
- **뉴욕은 건물 사면 하늘도 사는 것 아닌가?** → 그건 조닝의 개발권(FAR). 비행은 연방 관할.
  진짜 벽은 NYC §10-126 이착륙 금지.
- **로어맨해튼에 비행금지가 없는 게 확실한가?** → FAA 서비스 직접 조회함. 그 구역 4칸,
  전부 400ft. 0ft 없음. 국가안보 제한구역·금지구역·스타디움도 뉴욕 상공 0건.
- **건물마다 비행금지 표시가 있지 않나?** → 없음. 건물은 물리적 장애물로만 작동.
- **직접 조종은 런타임이 적용되나?** → 아니오. 별도 패키지·이미지·네트워크. 감사할 기록
  자체가 없음(`unrecorded_actions == actions`).
- **직접 조종을 빼버릴까?** → 권고: 계산은 유지(대조군이 없으면 주장이 증명 불가),
  지도에서만 기본으로 감춤. 이미 그렇게 해둠.

# E. Codex 인계 — 남은 일

우선순위 순. 각 항목은 "무엇을 / 어디를 / 어떻게 확인" 으로 씁니다.
전체 테스트: `PYTHONPATH=. python3 -m unittest discover -s tests` (65개) 와
`node --test tests/test_map.mjs` (16개). 둘 다 통과 상태에서 시작합니다.

## E1. 경로는 한 벌이고, 지나온 만큼 지워진다 (최우선)

**요구.** 노란 점선으로 경로 산출중 → 런타임이 통과시키면 **그 자리에서 초록으로 바뀌며**
진행 경로가 된다. 기체가 나아간 만큼 뒤쪽은 즉시 지워진다. 화면에 경로는 한 벌만 보인다.

**지금.** 같은 경로가 두 벌로 그려집니다 — 지면의 `approved-line`(선)과 고도의
`flightpath`(입체 회랑). 줌 14.5~15.5 구간에서 서로 교대하도록 방금 넣었으나
**실화면 검증 안 됨.** 뒤쪽 삭제는 지면 선에만 들어가 있습니다(`sliceCurve`).

**할 일.**
- `ui/map.html` `draw()`: 회랑(`ribbon`)도 기체의 현재 진행 위치에서 시작하는지 확인.
  지금은 `[point, ...v.route]` 라 이미 남은 구간만이지만, `v.route` 는 0.5초마다 갱신되므로
  그 사이 진행분이 남습니다. 지면 선처럼 `flown` 진행값으로 잘라야 합니다.
- 줌 교대가 실제로 한 벌만 보이게 하는지 확인. 안 되면 회랑 하나로 통일하고
  지면 선은 스테이지 재생(계산중/거절)에만 쓰기.
- 검증: 줌 13 / 15 / 17 에서 각각 경로가 **하나만** 보이고, 기체 뒤로 선이 남지 않을 것.

## E2. 기체 위에는 적재 박스만 (선은 전부 제거)

**요구.** 기체 대가리 위에 선이 있으면 안 된다. 그 자리에는 **실은 짐 개수만큼 정육각
박스가 쌓인 표시**가 있어야 한다.

**지금.** 고도 기둥·경로 커튼·궤적선은 제거 완료. 남은 건 회랑뿐이고 그건 진행 경로라
유지. **박스 스택은 미구현.**

**할 일.**
- `sim/world.py` `Vehicle` 에 `load: int` 추가. `PARCELS_PER_TRIP = 3` 정도.
- `ui/map-route.mjs` 에 `hexStack(lat, lon, count)` — 정육각 폴리곤을 개수만큼
  `base = i*3.5, height = base+3` 로 쌓아 반환. `column()` 을 지우고 이걸로 대체.
- `ui/map.html` 에 `cargo` 소스 + `fill-extrusion` 레이어. 기체 색으로.
- 검증: 적재 3이면 육각 3개, 하역할 때마다 하나씩 줄어들 것.

## E3. 적재 → 이륙 → 착륙 → 하역 순환과 문구

**요구.** 시나리오 시작 시 **전 기체가 창고(이륙장)에서 짐을 싣고** 있어야 한다.
그 뒤 landing / loading / landing / loading 이 반복되고, 기체 옆에
`LOADING…` `LANDING…` `UNLOADING…` 문구가 뜬다.

**지금.** 상태 세 개(`loading` / `landing` / `dropping`)와 기체 옆 문구는 구현됨
(`WORKING` 집합, `text-field` 의 `work` 속성). **순환이 없음** — 기체는 창고로 돌아오지
않고, 배달을 마치면 그 자리에서 다음 주문을 받습니다. 시작 위치도 창고 상공입니다.

**할 일.**
- `fresh_fleet()`: 기체를 이륙장 좌표에 `state="loading"`, `alt=0`, `work_ticks=LOAD_TICKS`
  로 세우고 시작.
- `_deliver()`: `load -= 1`. 남으면 다음 주문 배정, 0이면 `job` 을 비우고 복귀 대상으로.
- `attache/agent/detect.py`: `load == 0` 이고 이륙장에 없으면 `needs_reload` 개념을 내고,
  `propose.by_rule` 이 `reserve_pad` 를 내게 함. **두 세계가 같은 detect 를 쓰므로 여기 한 곳만.**
- `act()` 의 `depart`: 이미 `loading` 으로 들어가고 `LOAD_TICKS` 뒤 `cruising` 이 됨.
  거기서 `load = PARCELS_PER_TRIP` 을 채우면 됩니다.
- 검증: 한 판에서 각 기체가 창고 → 배달 3건 → 창고 순환을 최소 한 바퀴 돌 것.

## E4. 거절 사례가 많이 보여야 한다

**요구.** 브루클린에서 출발해 직선으로 가면 비행금지 구역을 뚫는다 → 런타임이 거절 →
허용 구역으로 우회해서 목적지(예: West New York)까지. 이런 장면이 자주 나와야 한다.

**지금.** 거절은 나오지만 대부분 **건물**(`leg 1 enters BUILDING 73 m`)입니다.
FAA 0ft 격자는 로어맨해튼에 없고(직접 조회로 확인), 퀸스·LGA·TEB 쪽에만 있습니다.
배달 반경이 4km 라 그쪽을 지나는 직선이 잘 안 생깁니다.

**할 일 (택1 또는 병행).**
- `SERVICE_RADIUS_M` 을 늘리고 배달지를 허드슨 건너(West New York, 40.78/-74.01)나
  퀸스 쪽까지 포함 → 직선이 0ft 격자를 관통 → 거절·우회가 자주 발생.
  **주의: 반경을 늘리면 왕복 시간이 늘어 한 판의 배달 수가 줄어듭니다.**
- 동적 구역(`ZONE`)을 더 크게/더 오래 열어 항로 위에 두기. 지금은 이스트빌리지
  600×700m, 560~900틱.
- 검증: 한 판에서 `airspace` 거절이 최소 5건, 그중 0ft 격자 사유가 절반 이상.

# F. 절대 어기지 말 것

1. **화면에 있는 것은 전부 뜻이 있어야 한다.** 뜻을 모르겠는 표시는 뺀다.
   (고도 기둥, 경로 커튼, 궤적선이 이래서 사라졌다)
2. **판정 전에 결과를 보여주지 않는다.** 초록은 승인 뒤에만.
3. **런타임이 관리할 것과 아닌 것을 구분한다.** 배터리 관리·기체 정비는 운영사의 몫.
   밖에서 도착해 즉시 강제돼야 하는 규칙만 런타임.
4. **한 화면에 한 언어.** EN/KR 토글.
5. **부산스러우면 뺀다.** 선을 더하기 전에 뺄 것을 먼저 찾는다.
6. **직결 쪽을 일부러 못나게 만들지 않는다.** 같은 씨앗·같은 감지·같은 신청서 작성기.
   다른 것은 배선뿐이어야 한다.
7. **판정 로직은 `attache/core/geo.first_breach` 하나뿐이다.** 두 번 적으면 반드시 갈라진다.
