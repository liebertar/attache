Attaché — 드론이 뭔가 하기 전에 반드시 지나야 하는 관문(런타임)을 보여주는 데모다.
같은 기단을 두 배선으로 돌린다: 하나는 런타임에 신청서를 내고 승인받아야 움직이고,
하나는 조종장치를 직접 만진다. 지도(ui/map.html)가 그 차이를 보여주는 화면이다.

## 먼저 읽을 것
docs/REQUIREMENTS.md — 사용자가 말한 요구사항 전부와 남은 일이 정리돼 있다.
이게 명세다. 특히 E0(화면 규칙), F0(선 그리는 순서), G(어기면 안 되는 원칙)를 먼저 읽어라.
HANDOFF.md 는 구조 설명이지만 일부 낡았다 — 두 세계 점수판 숫자와 "84% 반려" 서술은 틀렸다.

PYTHONPATH=. python3 -m unittest discover -s tests # 65개

점수판의 런타임(guarded) 열이 전부 0인지 확인해라. 그게 이 프로젝트가 주장하는 전부다.

## 작업 순서
E0-1 지면 선 제거 (공중 회랑만) → E0-3 공역 구역이 경로 가리는 것 (바닥 채색 권장)
→ E4 기체 4대 (한 줄) → E1 적재 순환 → E0-4/E0-5 (E1 끝나야 살아남)
→ E3 맨해튼 우회 시나리오 → E5 순항 고도는 사용자에게 물어라

## 반드시 지킬 것
1. 화면에 있는 것은 전부 뜻이 있어야 한다. 모르겠는 표시는 뺀다.
   (고도 기둥·경로 커튼·궤적선이 이래서 이미 사라졌다. 다시 넣지 마라)
2. 판정 전에 결과를 보여주지 마라. 초록은 승인 뒤에만.
3. 선은 새로 그리지 않는다. 같은 선의 색이 노랑→빨강 또는 노랑→초록으로 바뀐다.
4. 런타임이 관리할 것과 아닌 것을 구분해라. 배터리·정비는 운영사 몫.
   밖에서 도착해 즉시 강제돼야 하는 규칙만 런타임.
5. 판정 로직은 attache/core/geo.first_breach 하나뿐이다. 두 번 적으면 반드시 갈라진다.
   (계획기가 격자점만 보고 판정자가 선분을 봐서 승인이 0건이던 버그가 실제로 있었다)
6. 직결(direct) 쪽을 일부러 못나게 만들지 마라. 같은 씨앗·같은 감지 코드·같은 신청서
   작성기를 쓴다. 다른 것은 배선뿐이어야 한다.
7. 한 화면에 한 언어. EN/KR 토글이 있다.

## 이 코드베이스의 함정
- 같은 값을 두 곳에 적으면 반드시 갈라진다. 이 세션에서만 다섯 번 터졌다:
  라우터/판정자, 비행금지 구역 도형 2벌, 예산 한도 2벌, 순항 고도 2벌, 착륙대 이름 2벌.
  값을 쓰기 전에 이미 어디에 있는지 먼저 찾아라.
- tests/test_two_worlds.py 는 자체 에이전트 코드(GuardedSide/DirectSide)를 들고 있다.
  attache/agent/loop.py 를 고치면 여기도 같이 봐야 한다.
- MapLibre 5.9 에는 심볼을 고도에 띄우는 기능이 없다(symbol-z-offset 부재, 번들에서 확인).
  그래서 기체와 짐을 fill-extrusion 으로 그린다. 아이콘으로 되돌리지 마라.
- 화면 검증은 눈으로 해라. 테스트만 통과하고 화면은 깨진 경우가 반복해서 나왔다.
  브라우저가 없으면 playwright 로 스크린샷을 찍어서 직접 봐라
  (chromium.launch({channel:'chrome'}) 로 설치된 Chrome 을 쓸 수 있다).
- 커밋은 type(scope): 영어 subject + 한글 불릿 body. 왜 바꿨는지 위주로.

## 자주 걸리는 것
- 공역 구역을 입체로 세우면 드론 경로를 가리고, 반투명이 여러 겹 겹치면 깨져 보인다.
  사용자는 **바닥에 색만 칠하는 쪽**을 원한다. 조건은 하나다 — 경로가 절대 안 가려질 것.
  더 나은 방법이 있으면 그쪽을 써도 된다.
